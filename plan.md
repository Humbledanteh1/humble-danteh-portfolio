# Portfolio demo projects — implementation plan

## User-approved scope
Create original demo projects from scratch to replace all placeholder cards: one e-commerce storefront, one business website, and two distinct AI-agent prototypes. The user wants an automation project later, so automation is explicitly out of this phase. These are self-initiated portfolio demos, not client work; do not invent client identities, deployment claims, or performance results.

## Implementation approach
Keep the existing React + TypeScript + Vite portfolio and GitHub Pages deployment. Add four self-contained, responsive demo experiences accessible through hash routes (`#/demo/<slug>`) so they work on both local preview and the repository's project-site URL without a routing dependency or server. The home page will show four project cards with honest demo labels, concise case-study summaries, and links to each working demo. Demo pages will offer a visible return-to-portfolio link.

- E-commerce: an original home-goods storefront with product browsing, category filters, cart count, and a cart drawer/panel. Product imagery is custom-generated.
- Business website: an original bakery site with menu, location/hours, and a local preorder/visit CTA (no real order submission).
- AI agent 1: product discovery with a curated product knowledge base and interactive example conversation. Clearly disclose that responses are scripted in this front-end prototype, not generated by a live model.
- AI agent 2: order-support triage against explicit sample order records with simulated next-step suggestions. Clearly disclose that no real orders or live AI are connected.
- No external API, payment, real data capture, client claim, or automation in this phase.

## Project structure
- `src/App.tsx`: existing portfolio shell, project list and hash-route dispatch.
- `src/ProjectDemos.tsx`: standalone demo views and interactions, separated by demo type.
- `src/ProjectDemos.css`: responsive demo-specific visual systems and UI states.
- `public/demo-assets/`: original e-commerce product and bakery hero images.
- `plan.md` and `TODO.md`: project scope and completion tracking.

## Design direction
- **Design movement:** editorial commerce with a crafted, contemporary digital-studio sensibility.
- **Core principles:** tangible and specific; calm hierarchy; useful interactions; honest demo status.
- **Color philosophy:** warm ivory and clay for home goods, butter and espresso for the bakery, and deep ink with bright mint/cyan for the agent tools. Each demo should feel like its own plausible product while retaining the parent portfolio's polished editorial quality.
- **Layout paradigm:** spacious, left-aligned editorial storefronts and layered product grids; bakery pages with asymmetric photo/text split; AI demos use compact two-column workspaces that collapse naturally on mobile.
- **Signature elements:** serif display headlines, small mono category labels, restrained pill controls, soft product shadows, and a small visible “Concept demo” label.
- **Interaction philosophy:** immediate, reversible interactions; cart and agent responses update in place; any form only shows a local prototype confirmation and never submits personal data.
- **Animation:** subtle hover lift and short opacity/position transitions; honor reduced-motion preferences; no looping decorative animation.
- **Typography system:** reuse existing loaded Manrope, Space Mono, and DM Serif Display; use DM Serif Display for editorial headlines, Manrope for reading text and controls, Space Mono for metadata.
- **Brand essence:** practical digital prototypes that show how commerce, websites, and AI can solve clear user problems; thoughtful, capable, candid.
- **Brand voice:** specific and helpful, avoiding inflated claims. Example: “Find a piece that fits your space.” “A clear next step, without the support queue.”
- **Wordmarks:** text-based original demo identities (Hearth & Form, Sunday Bakehouse, Findwell, and Orderwise) set in typography; no generated wordmark artwork.
- **Signature color:** Vertigo portfolio retains blue; each demo receives a warm or dark interface palette as defined above.

## Honest case-study framing
Every project is labeled “Self-initiated demo.” Case-study copy describes the design problem and the implemented feature set, but does not imply customer adoption, external clients, measurable business impact, live model integration, or real transactions.
